# Kursovaya

Учебный проект на Java, реализующий собственную файловую систему в виде дискового образа.

Проект моделирует основные компоненты файловой системы: суперблок, битовые карты свободных блоков и inode, список inode, корневой каталог, хранение файлов, пользователей и групп. Взаимодействие с системой выполняется через консольный интерфейс.

## Возможности

* создание и инициализация дискового образа;
* хранение структуры файловой системы в одном файле;
* работа с суперблоком;
* управление битовой картой свободных блоков;
* управление битовой картой inode;
* выделение свободных inode и блоков данных;
* хранение информации о файлах в inode;
* корневой каталог;
* создание файлов;
* удаление файлов;
* редактирование файлов;
* копирование файлов;
* открытие и чтение файлов;
* создание пользовательских учетных записей;
* авторизация пользователей;
* разделение пользователей и групп;
* проверка доступа к файлам;
* хранение паролей в виде MD5-хеша;
* просмотр внутренних структур файловой системы;
* простой планировщик событий.

## Архитектура

При запуске программа создает файл `System.dat` и заново инициализирует его как дисковый образ.

Общая структура выглядит следующим образом:

```text
System.dat
│
├── SuperBlock
│   └── информация о файловой системе
│
├── Block Bitmap
│   └── занятые и свободные блоки
│
├── Inode Bitmap
│   └── занятые и свободные inode
│
├── Inode List
│   └── метаданные файлов
│
├── Root Directory
│   └── записи корневого каталога
│
└── Data
    ├── пользователи
    ├── группы
    └── содержимое файлов
```

Для работы с дисковым образом используется `RandomAccessFile`, поэтому различные структуры файловой системы находятся по фиксированным смещениям внутри `System.dat`.

## Основные параметры

| Параметр                      |  Значение |
| ----------------------------- | --------: |
| Размер дискового образа       |    50 MiB |
| Размер блока/кластера         | 2048 байт |
| Количество inode              |       512 |
| Записей корневого каталога    |        30 |
| Прямых адресов данных в inode |        12 |

Дисковый образ создается непосредственно при запуске программы.

## Структура диска

Проект использует фиксированные смещения для основных разделов:

| Раздел         | Смещение |
| -------------- | -------: |
| SuperBlock     |        0 |
| Block Bitmap   |     2049 |
| Inode Bitmap   |     6145 |
| Inode List     |    10241 |
| Root Directory |    47105 |
| Data           |    49153 |

Эти значения задаются в `SuperBlock.java` и используются классом `CursorMovement` для перехода между разделами дискового образа.

## SuperBlock

`SuperBlock` содержит основные параметры файловой системы:

* размер кластера;
* размер битовой карты блоков;
* размер битовой карты inode;
* общее количество inode;
* количество свободных inode;
* количество свободных блоков;
* смещения основных разделов диска.

При инициализации файловой системы устанавливается размер `System.dat`, после чего записывается информация о структуре диска.

## Bitmaps

Для отслеживания свободного пространства используются две битовые карты.

### Block Bitmap

`BlocksBitMap` отвечает за состояние блоков данных.

При создании файла программа ищет свободный блок в битовой карте и отмечает его как занятый.

### Inode Bitmap

`InodesBitMap` аналогично используется для поиска свободного inode.

`BitWork` содержит операции, необходимые для установки и сброса отдельных битов при выделении ресурсов.

## Inodes

`InodesList` хранит метаданные файлов.

В структуре inode предусмотрены:

* тип файла;
* права доступа;
* количество ссылок;
* UID владельца;
* GID группы;
* размер файла;
* даты создания и изменения;
* адреса блоков данных;
* поле для косвенной адресации.

В проекте используется 512 inode.

## Корневой каталог

`CatalogWork` отвечает за работу с корневым каталогом.

Запись каталога содержит информацию о:

* имени файла;
* расширении;
* номере inode;
* дополнительных данных записи.

Корневой каталог рассчитан на 30 записей.

Через него выполняется поиск файлов, проверка их существования, удаление и другие операции.

## Файлы

Для работы с обычными файлами используются `FileWork` и `Data`.

Поддерживаются следующие операции:

```text
mkfile <filename>    создать файл
rmfile <filename>    удалить файл
edfile <filename>    изменить файл
cpfile <filename>    скопировать файл
opfile <filename>    открыть файл
shdir                показать корневой каталог
```

При создании файла:

1. проверяется имя файла;
2. находится свободный inode;
3. находится свободный блок данных;
4. информация записывается в inode;
5. содержимое сохраняется в области данных;
6. запись добавляется в корневой каталог.

## Пользователи и группы

Файловая система содержит собственную модель пользователей и групп.

При запуске создаются служебные данные для пользователей и групп. Новые пользователи могут быть зарегистрированы непосредственно через консоль.

Для пользователя хранятся:

* UID;
* GID;
* логин;
* хеш пароля;
* связанный каталог.

При регистрации действуют ограничения на длину логина и пароля.

## Авторизация

После запуска пользователь может выбрать:

```text
1. Create new user account
2. Log in to existing user account
```

Пароль перед проверкой преобразуется функцией `md5Custom()` из класса `Crypter`.

В проекте используется стандартный Java `MessageDigest` с алгоритмом MD5.

> MD5 используется здесь как часть учебной реализации. Для реальной системы хранения паролей такой подход не рекомендуется.

## Права доступа

Файлы связаны с UID владельца и GID группы.

В текущей реализации проверка доступа учитывает принадлежность пользователя к владельцу или соответствующей группе.

При этом inode также содержит поля, предназначенные для хранения информации о правах доступа.

## Командная строка

После авторизации пользователь получает собственную командную строку.

Пример:

```text
username>
```

Основные команды:

```text
mkfile <filename>    создать файл
rmfile <filename>    удалить файл
edfile <filename>    редактировать файл
cpfile <filename>    скопировать файл
opfile <filename>    открыть файл
shdir                показать содержимое корневого каталога
planner              запустить планировщик
logout               выйти из текущей учетной записи
shutdown             завершить работу файловой системы
-help                показать список команд
```

Также присутствуют диагностические команды для просмотра внутренних структур:

```text
-getsb               прочитать SuperBlock
-setsb               изменить SuperBlock
-getbmb              прочитать Block Bitmap
-getbmi              прочитать Inode Bitmap
-getilist            прочитать список inode
-getrcat             прочитать корневой каталог
-tobit <byte>        представить байт в двоичном виде
-toMD5 <text>        получить MD5-хеш строки
```

## Запуск

Для запуска требуется JDK с поддержкой используемого в проекте Java-кода.

Точка входа:

```text
com.crosska.Main
```

При запуске:

1. удаляется существующий `System.dat`;
2. создается новый дисковый образ;
3. инициализируется SuperBlock;
4. создаются битовые карты;
5. создается список inode;
6. создаются служебные файлы пользователей и групп;
7. запускается консоль файловой системы.

Поскольку `System.dat` удаляется при каждом запуске, данные предыдущего запуска не сохраняются.

## Ограничения

Проект является учебной реализацией и не предназначен для использования в качестве реальной файловой системы.

Некоторые ограничения текущей реализации:

* фиксированный размер дискового образа;
* фиксированная структура разделов;
* ограниченное количество inode;
* ограниченный размер корневого каталога;
* работа преимущественно с корневым каталогом;
* консольный интерфейс;
* отсутствие полноценной POSIX-модели прав доступа;
* MD5 используется для хранения хешей паролей;
* некоторые параметры файловой системы жестко заданы в исходном коде;
* существующий `System.dat` удаляется при запуске.

Проект следует рассматривать прежде всего как демонстрацию принципов организации файловой системы и работы с низкоуровневым представлением данных.

## Назначение проекта

Проект разработан как учебная курсовая работа для изучения внутреннего устройства файловых систем.

Основной интерес представляет не пользовательский интерфейс, а реализация собственных структур хранения:

```text
SuperBlock
    ↓
Bitmaps
    ↓
Inodes
    ↓
Root Directory
    ↓
Data
```

Таким образом, проект позволяет на практике рассмотреть, как файловая система может организовывать пространство диска, находить свободные ресурсы, связывать записи каталога с inode и хранить содержимое файлов.
